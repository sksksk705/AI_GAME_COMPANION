# 발언 판단 모델 비교: Jev와 상용 LLM

> 확인일: 2026-10-07. 공식 모델·API 자료의 기능과 공시 가격을 비교했다. 우리 게임 입력의 실제 모델 정확도·지연을 측정한 보고서는 아니다.

**Jev 1.13은 발언 정책 판단의 후보로 적합하다.** 다만 텍스트만 읽고 typed decision을 반환하므로 화면을 읽는 기존 비전 판단 요청 전체를 바로 교체할 수 없다. 현재 앱은 한 요청에서 전후 화면의 사건·근거와 발언 여부를 함께 얻는다. Jev로 역할을 나누려면 관찰 사실을 먼저 텍스트로 만들어야 한다.

## 1. 확인한 기능과 가격

가격은 USD/100만 토큰, 캐시 할인 제외 공시값이다. 이미지·숨은 추론·제공자 설정에 따른 실제 청구는 별도 확인한다.

| 모델 | 입력 / 출력 가격 | 직접 이미지 입력 | 반환 방식 | 비교에서의 역할 |
|---|---:|---|---|---|
| `typesafe/jev-1.13` | $0.042 / $0 | 불가 | Choice/Noul/Score와 확률 | 텍스트로 정리된 사건과 대화의 발언 정책 판단 |
| `openai/gpt-4.1-nano` | $0.10 / $0.40 | 가능 | 구조화 JSON | 비전·텍스트 판단 후보, 첫 비교 대상 |
| `google/gemini-2.5-flash-lite` | $0.10 / $0.40 | 가능 | 구조화 JSON | 비전·텍스트 판단 후보, 첫 비교 대상 |
| `openai/gpt-5-nano` | $0.05 / $0.40 | 가능 | 구조화 JSON | 추가 비교 후보. 추론 설정·사용량도 함께 확인 |
| `openai/gpt-6-luna` | $0.10 / $0.50 | 가능 | 구조화 JSON | 같은 관찰을 받은 일반 LLM 기준 |

출처: [OpenRouter 모델 API](https://openrouter.ai/api/v1/models), [Jev 모델·제공자](https://openrouter.ai/typesafe/jev-1.13), [Jev Endpoints API](https://openrouter.ai/api/v1/models/typesafe/jev-1.13/endpoints). 기존 작업 PC의 Luna Pro와 표의 일반 Luna는 실행 모드가 다르다. 토큰 단가가 같다고 요청 총비용이나 지연이 같지는 않다.

### Jev의 장점과 제약

- 생성 문장 없이 타입과 확률을 반환한다. `Noul`은 yes의 확률인 `noul` 숫자로, 발언 여부 임계값을 바꿔 비교할 수 있다.
- 출력 토큰 비용은 무료이고 입력 문맥은 32,000토큰이다. 공식 제공자는 TypeSafe이다.
- 모델 페이지는 P50 0.20초를 표시했다. 전체 지역·최근 1주·해당 제공자의 공개 통계이며 **우리 입력의 지연이나 다른 모델과 같은 조건의 실험 결과가 아니다.** 다른 후보의 같은 조건 지연은 측정하지 않았다.
- [TypeSafe System One 문서](https://docs.typesafe.ai/concepts/system-one)는 텍스트만 지원한다고 명시한다. 이미지·오디오·영상, 자유 문장과 판단 이유는 반환하지 않는다.
- [OpenRouter Jev 문서](https://openrouter.ai/docs/guides/community/jev)에 따르면 일반 `/api/v1/chat/completions`가 아닌 **`POST /api/alpha/decisions`**를 사용한다. 기존 이미지/구조화 답변 모델 선택 목록에 단순히 ID만 넣는 방식으로는 동작하지 않는다.
- `typesafe/jev-router`는 다른 채팅 모델로 라우팅하는 별도 제품이다. `typesafe/jev-1.13`과 입력·출력·비용을 혼동하지 않는다.
- 제조사는 확률 보정을 설명하지만, 한국어 게임·사용자 취향에서 보정이 유지되는지는 검증해야 한다. 확률 하나가 맞는 판단의 보증은 아니다.

## 2. 우리 앱에서 비교할 두 수준

### A. 발언 정책만 비교

같은 관찰 패킷을 모든 모델에 제공한다.

```text
확인한 전후 사건·불확실성·관찰 시점
+ 플레이어의 발화·집중 상태
+ 최근 동료 발언과 관련 기억
→ Jev / nano / Flash-Lite / Luna
→ 발언 또는 침묵
```

Jev는 `Noul`로, LLM은 `{should_speak: boolean}`으로 답한다. 같은 자연어 판정 기준과 같은 데이터로 비교한다. LLM에 스스로 확률을 만들어내라고 요청해 Jev의 보정된 확률과 동일한 것으로 취급하지 않는다.

이 비교는 정책 판단의 품질·추가 비용·지연을 분리한다. 입력에 없는 실제 화면을 모델이 봤다고 평가하지 않는다. 관찰 패킷이 틀리면 Jev도 잘못 판단할 수 있다.

quiet·입력 중·확인된 중복 키·쿨다운 등 이미 앱이 아는 조건은 로컬 규칙으로 먼저 차단한다. 단순 bool 조합만 있는 예제로 전용 모델이 필요하다고 결론내리지 않는다. 실제 평가에는 표현이 다른 동일 사건, 서로 다른 섬의 숫자 비교, 원인 추정과 직접 관찰의 구분, 사용자 취향·직전 대화에 따라 반응 여부가 달라지는 경우를 포함한다.

### B. 화면 인식까지 포함한 전체 처리 비교

| 구성 | 해석 |
|---|---|
| 소형 비전 모델 → 필요하면 대사 모델 | 화면 사건과 발언 판단을 함께 얻는 현재 구조의 후보 |
| 비전 관찰 → Jev 정책 → 필요하면 대사 모델 | 역할을 분리한 구성. 매번 관찰 API를 새로 호출하면 단계와 비용이 늘어남 |
| 이미 확보된 관찰 사실 → Jev → 필요하면 대사 모델 | 다른 기능에서도 쓰는 사실·OCR·게임 상태가 있으면 전용 정책 판단의 이점을 검증하기 좋음 |

비전 관찰을 공통으로 캐시해 정책 모델을 비교할 수 있지만, 전체 비용을 보고할 때에는 해당 관찰의 생성 비용을 포함한다. 새 화면이 왔는데 오래된 텍스트 사실만 사용하면 사건을 놓칠 수 있으므로 시점·관찰 공백·원본 참조를 유지한다.

**권장 순서:** 먼저 Jev·GPT-4.1 nano·Flash-Lite를 같은 한국어 관찰에 평가하고 Luna를 기준으로 둔다. 이후 가장 좋은 정책 후보를 비전 인식과 연결해 전체 비용·지연·놓친 사건·불필요한 반응을 비교한다. 현재 자동 판단 모델을 Jev로 기본 변경하지 않았다.

## 3. 비용 예시와 공개된 실험의 한계

같은 정책 요청이 입력 1,000토큰, LLM 출력 100토큰이라고 가정하면 계산상 Jev는 $0.000042, GPT-4.1 nano/Flash-Lite는 $0.00014, GPT-5 nano는 $0.00009, Luna는 $0.00015이다. 실제 입력에는 판정 기준도 포함되고 토크나이저가 다르며 추론 토큰이 추가될 수 있다. **이 계산은 측정 결과도 전체 컴패니언 비용도 아니다.**

[OpenRouter의 Jev cascade 예제](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-verified-cascade)는 지원 문서 질문 50개에서 저렴한 답변+Jev 검증이 $0.012, 강한 Astra만 사용한 경우 $0.175라고 보고한다. 그러나 같은 예제의 Luna 단독은 $0.004이며, 최종 회차에서 Luna와 cascade는 모두 틀린 답변 전송 0건이었다. 원문도 회차별 모델·채점 잡음을 설명한다. 이는 작고 업체가 작성한 문서 기반 실험이며 게임 발언 타이밍의 우월성을 입증하지 않는다.

따라서 이미 소형 LLM이나 로컬 규칙으로 잘 판단한다면 Jev 추가가 항상 비용을 줄이지는 않는다. 평가 목적은 가장 저렴한 모델명 찾기가 아니라 원하는 반응 품질을 유지하는 전체 구성을 찾는 것이다.

## 4. 준비한 비교 도구

예제 입력: [JUDGE_BENCHMARK.example.json](cases/JUDGE_BENCHMARK.example.json). **4개 사례는 합성 형식 예제이며 실제 플레이 관찰이 아니다.** 실제 관찰 패킷과 사람이 정한 반응/침묵 판정으로 바꾼 뒤 비교한다.

계획 확인은 API를 호출하지 않는다.

```powershell
npm run judge:plan -- --manifest docs/cases/JUDGE_BENCHMARK.example.json
```

저장된 키가 있는 Windows PC에서 앱을 닫고, 전송 동의와 기존 일일 한도로 실행한다.

```powershell
npm run evaluate -- --live --judges .local/bench/judges.json
```

- 예제 4모델×4사례×1회는 총 16회다. 전체 비교가 남은 한도 안에 들어가지 않으면 호출 전 중지한다. 한도를 자동으로 올리지 않는다.
- 모든 모델은 동일 텍스트 상태를 받는다. `expected`와 데이터 출처의 라벨은 모델에게 보내지 않는다. 모델 실행 순서는 사례마다 회전한다.
- Jev의 기본 예제 임계값 0.8은 미보정 가설이다. Proact-VL의 학습된 헤드 임계값을 가져온 것이 아니다. 검증용 자료로 임계값을 선택하고 별도 평가 자료로 확인한다.
- `.local/judge-evaluation-*.json`에 요청한 모델과 응답한 스냅샷·제공자/요청 ID·확률·실제 토큰/보고 비용·지연·불필요한 발언·놓친 사건·정밀도/재현율·실패 수를 기록한다.
- 정확도에 해당하는 `labelAgreement`는 **제공한 정책 라벨과의 일치율**이다. 실패를 제외한 분모와 실패 횟수를 함께 기록한다. 이미지 이해 정확도나 실제 사용자 만족도가 아니다.
- P50/P95는 완료한 요청의 전체 수신·검증 시간이다. 첫 토큰 지연이 아니다. 작은 예제의 백분위는 안정적인 서비스 지연 추정치로 사용하지 않는다.
- 실패를 자동 재전송하지 않으며 부분 결과와 중지 이유를 기록한다. 키·인증 헤더는 보고서에 넣지 않는다.

텍스트 정책 비교 도구는 기존 앱의 전체 비전 판단 스키마를 대체하지 않는다. Jev는 근거 문장·사건 키·전후 관찰 내용을 생성하지 않으므로 향후 연동에서 비전 관찰 결과를 유지하고 정책 판정만 더해야 한다.

## 5. 이번 확인 결과

- 공식 모델·제공자·튜토리얼·Decisions API·TypeSafe 문서를 직접 읽었다.
- `node test/check.cjs` 통과. 실제 SQLite와 모의 응답으로 Jev/채팅의 다른 경로, Noul 확률 검증, 동일 관찰 전송, 정답 미전송, 비교 예산 사전 검사와 집계 경계를 확인했다.
- 호출 없는 계획 출력으로 16회 비교와 예제 데이터 출처를 확인했다.
- 현재 클라우드에는 상용 API 키가 없다. 이번 작업에서 실제 Jev나 비교 LLM을 호출하지 않았고, 모델별 게임 품질·속도 순위를 만들지 않았다. 기존 작업 PC의 9회 가이드 평가를 이 정책 비교 결과로 사용하지 않는다.
