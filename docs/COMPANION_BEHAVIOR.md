# 게임 플레이 중 컴패니언 경험·응답 명세

> 상태: 행동 명세 v0.4 / 2026-10-07 — 작은 동료·말풍선·선택적 인사 반영
> 상위 문서: [PLAN.md](../PLAN.md)  
> 목적: 동료가 언제 반응하고 무엇을 어떤 형식으로 말하는지, 사용자의 다음 행동과 기억에 어떻게 연결하는지 정의한다.  
> 예시는 가상의 관찰·대화다. 실제 게임 상태, 출시 기능 또는 검증된 성능을 나타내지 않는다.

## 1. 동료의 역할과 말투

동료는 같은 게임 장면을 보고 지난 이야기를 기억하는 대화 상대다. 사용자가 직접 결정하고 플레이하며, 목표를 세우거나 도움을 요청하지 않아도 함께할 수 있다. **상황 반응, 잡담, 공감, 기억 이어가기**가 기본이고 문제 조사·선택 비교·배치 설명은 필요한 순간에 제공한다.

사전 지식과 함께 현재 플레이에서 배운 경험을 활용한다. “이런 건 어때?”라는 작은 제안, 사용자의 선택, 실제 적용과 결과 확인을 이어가며 모르는 부분과 실패도 기억한다. 경험은 조건과 출처를 유지하고 한 번의 성공을 보편 규칙으로 확정하지 않는다. 상세 흐름은 [공동 학습·화면 설명 명세](SHARED_LEARNING_AND_LIVE_GUIDANCE.md)를 따른다.

- 한국어 기본 말투는 편한 반말이다. 이름, 차분함·장난스러움·함께 생각하는 성향, 존댓말 여부와 대화 선호를 사용자가 바꿀 수 있다.
- 대사는 기본 1–2문장이다. 성과에는 짧게 함께 반응하고, 막힘에는 먼저 상황을 받아준다. 요청하지 않은 강의·조언·목표 확인을 매번 붙이지 않는다.
- 최근 대화의 순서와 사용자의 결정을 함께 전달한다. AI가 말한 내용을 사용자 확정 사실로 승격하지 않는다.
- 최근 대화 밖의 관련 결정·시도 결과도 찾아 활용한다. 사용자가 매번 따로 메모하지 않아도 중요한 선택의 맥락을 이어갈 수 있어야 한다.
- 근거·가설·추가 확인은 상세 영역에 둔다. 중요한 미확인은 짧은 대사 안에서도 정직하게 표현한다.
- 추천 이유를 짧게 설명하고, 관찰 사실과 추정을 다른 문장으로 표현한다.
- “최적”, “반드시”, “무조건 해결”은 충분한 규칙·데이터 검증 없이 쓰지 않는다.
- 실패를 비난하거나 이미 아는 기본 설명을 매번 반복하지 않는다.
- 기억을 활용할 때 출처가 있는 과거 행동·말만 언급한다. 친밀감을 위해 경험을 지어내지 않는다.
- 사용자의 기분·좌절·의도를 화면 변화만으로 확정하지 않는다.
- 동료가 실제로 본 범위와 마지막 관찰 시점을 사용자가 확인할 수 있어야 한다.
- 게임에 자동으로 행동하지 않는다. “바꿔뒀어요”는 사용자가 적용한 사실이 확인된 경우에도 AI가 수행한 것처럼 말하지 않는다.
- 경험을 활용할 때 “지난번엔 이 조건에서 도움이 됐어. 이번에도 먼저 확인해볼까?”처럼 적용 범위와 확인 행동을 짧게 연결한다. 정정·거절·다른 취향은 다음 제안에 반영한다.

[Questie의 기능](https://www.questie.ai/ko/features), [FAQ](https://www.questie.ai/ko/faq), [대화 프롬프트 안내](https://www.questie.ai/prompting)를 참고했다. 화면을 함께 보는 경험, 대화 길이·타이밍·기억·성향을 반영하며 사용자 선택에 따라 텍스트부터 구현한다. 음성·정교한 캐릭터 커스터마이징·다인 파티나 공개 페이지의 속도 수치는 이 초안의 구현·성능 약속이 아니다.

예시: “배를 더 사야 하나?” → “홉이 부족한 건지, 배가 못 옮기는 건지부터 같이 보자. 지금 홉 섬에는 재고가 쌓이고 있어?” / “오늘은 효율 말고 꾸미기만 할래.” → “좋아. 오늘은 마음에 드는 풍경부터 만들자.” 이 대화는 예시이며 실제 화면을 관찰한 결과가 아니다.

## 2. 두 개의 독립 설정: 관찰과 발언

### 관찰 설정

- 관찰 OFF: 새로운 캡처·분석·자동 사건 기록을 중지한다. 기존 기록의 열람·대화는 가능하다.
- 관찰 ON: 선택한 창을 수집하고 허용된 범위·비용 안에서 분석·기록한다.
- 캡처 가능 상태와 원격 분석 가능 상태를 따로 표시한다. 비용 한도·네트워크 장애로 분석이 중지돼도 이를 숨기지 않는다.

### 발언 모드

| 모드 | 먼저 말하는 범위 | 사용자 질문에 대한 답변 |
| --- | --- | --- |
| 조용히 관찰 — 기본값 | 게임 내용에 대한 선제 발언 없음. 관찰·비용·오류 상태는 상태 영역에서 표시 | 즉시 요청 답변 흐름으로 처리 |
| 목표 감시 | 사용자가 고른 목표·문제·조건의 변화만 알림 | 동일 |
| 함께 플레이 | 허용한 감시 + 계획 확인·선택적 성과 반응·맥락 있는 개선 제안 | 동일, 선제 발언보다 우선 |

관찰 ON이 선제 발언 동의는 아니다. 같은 사건도 조용한 모드에서는 타임라인에만 남길 수 있다. 신규 모드는 사용자가 선택하며 자동으로 상향하지 않는다.

사용자는 감시할 항목을 구체적으로 고를 수 있다. 예: “이 생산단지 공급이 다시 끊기면 알려줘”, “현재 확장 계획과 충돌하는 부분을 찾아줘”. 정확히 관찰할 수 없는 조건은 등록 시 한계를 설명한다.

### 짧은 인사 — 로컬 동료 연출

`함께 플레이`의 별도 `가끔 짧은 인사 건네기` 설정으로 제공한다. 실시간 창을 관찰하며 최신 캡처가 있고, 대화창이 접혀 있고 보이며, 질문·분석이 없을 때만 전달한다. 관찰 시작·질문·직전 발언 이후 최소 4분, 세션당 최대 3회이며 AI 선제 발언과 10분 최대 3회 한도를 공유한다. 목표 감시·조용한 모드·리플레이·관찰 중지·숨김에서는 침묵한다.

“필요할 때 불러줘”처럼 게임 사실을 주장하지 않는 문장으로 `짧은 인사`를 표시한다. 이름·말투 설정에서 끌 수 있고 AI 연결·전송 동의를 자동으로 켜지 않는다. 외부 요청이나 학습 기억을 만들지 않는다. 이 정책은 게임의 전투·집중 상태를 알아내지 못하므로 실제 방해 정도를 플레이에서 평가한다. 게임 조언과 성과 반응은 기존 모델 후보 검증을 그대로 따른다.

## 3. 도움의 강도와 답변 길이

### 도움의 강도

- 함께 고민: 고려할 요소와 한두 가지 질문을 제시한다.
- 선택 비교: 후보별 장점·비용·위험을 비교한다.
- 추천 요청: 먼저 할 행동을 정하고 이유·조건·확인 방법을 설명한다.

이 설정은 발언 빈도와 독립이다. 사용자가 조용한 모드에서 명확한 추천을 요청할 수 있다. 직접 질문은 저장된 기본값보다 현재 요청을 우선한다.

### 답변 길이

| 단계 | 기본 형식 | 쓰는 상황 |
| --- | --- | --- |
| 짧은 반응 | 결론 1문장 + 선택적 버튼, 1–2문장 후보 | 선제 알림, 단순 확인 |
| 기본 대화 | 상황에 맞는 1–2문장, 필요할 때 가장 중요한 질문 하나 | 잡담·반응·일반 질문 |
| 도움 요청 | 짧은 대사 + 펼쳐보는 이유·다음 행동·이미지 | 조사·개념 설명 요청 |
| 상세 분석 | 근거 이미지·시간 순서·선택 비교·조건·검증 방법을 펼쳐 표시 | 사용자가 상세 설명 선택 또는 복잡한 설계 요청 |

문장 수는 UX 시작값이며 정보 누락을 강요하는 상한은 아니다. 첫 화면에 모든 분석을 펼치지 않는다. 자세한 근거와 비용·버전 조건은 상세 영역에 둔다.

## 4. 언제 반응하는가: 상황 목록

선제 발언은 각 상황의 관찰 조건 외에도 5절의 발언 정책을 통과해야 한다. 화면 분석 모델이 중요하다고 판단했다는 이유만으로 알림을 내보내지 않는다.

| ID | 상황 | 필요한 신호·맥락 | 반응·출력 | 선제 발언 조건 |
| --- | --- | --- | --- | --- |
| SC-01 | 게임 복귀·월드 선택 | 사용자가 월드 선택, 이전 계획과 최근 기록 존재 | 목표·미해결 문제·첫 행동 브리핑 | 기본은 동료 창의 브리핑 카드. 오버레이 알림·소리는 선택 |
| SC-02 | 자원·공급 부족 | 읽을 수 있는 부족 경고·통계, 같은 문제의 이전 관찰 | 무엇이 바뀌었는지 제시하고 생산·운송 조사 | 등록한 감시 또는 함께 플레이에서 허용한 중요 문제 |
| SC-03 | 생산이 정체됨 | 비교 가능한 여러 관찰, 가동·공급 관련 근거 | 확인된 구역 강조, 가능한 병목과 추가 확인 제안 | 감시 대상이어야 함. 화면이 정적이라는 사실만으로 발언 금지 |
| SC-04 | 전력·연결 등 기반 문제 | 현재 화면에서 확인한 경고와 대상 위치 | 짧은 문제 알림, 위치 표시, 확인 행동 | 최신 근거 + 허용한 감시. 다른 구역 전체 상태를 추정하지 않음 |
| SC-05 | 경제·재고 악화 추세 | 같은 기준·단위의 시점별 수치, 목표와 관련성 | 시점 비교와 악화 후보 원인 설명 | 지속성이 확인되고 사용자가 감시 허용 |
| SC-06 | 새 건설·큰 변경 | 실제 변경이 보이는 전후 화면, 기존 계획 | 먼저 사건 기록, 관련 계획을 확인 | 변경마다 발언하지 않음. 계획 충돌이 중요하고 허용된 경우만 |
| SC-07 | 같은 문제의 재발 | 이전 해결 기록과 같은 대상·증상 | 이전 조치와 이번 차이 비교 | 해결 후 새로 발생한 사건일 때, 단순 반복 관찰은 제외 |
| SC-08 | 배치·확장 기회 | 사용자의 설계 요청 또는 활성 목표, 공간·규칙 정보 | 표시된 현재 화면 + 개선 후보 + 개념 도면 | 비긴급 제안. 기본은 요청 시, 함께 플레이에서만 제한적 선제 제안 |
| SC-09 | 조치 후 변화 | 사용자가 적용했다고 말함 또는 실제 적용 근거, 확인 가능한 결과 | 전후 비교, 효과·부작용·미확인 항목 설명 | 진행 중인 조사에 대한 허용된 후속 확인 |
| SC-10 | 목표 달성·성과 | 목표 조건 충족 근거 또는 사용자 확인 | 짧은 인정, 완료 확인, 다음 계획 연결 | 성과 반응 설정 ON. 해결·달성을 화면만으로 과장하지 않음 |
| SC-11 | 사용자 질문·막힘 표현 | “왜?”, “다음은?”, “계속 안 돼”, 대상 선택 | 의도에 맞춘 조사·비교·추천 또는 최소 확인 질문 | 요청 응답이므로 선제 알림 쿨다운과 별개 |
| SC-12 | 세션 종료·월드 변경 | 명시적 종료, 창 종료 또는 월드 변경 | 관찰 종료, 세션 요약·다음 할 일 초안 | 기본은 조용한 요약 카드. 종료가 게임 저장 완료를 뜻하지 않음 |

추가 상황은 신호·근거·사용자 가치·발언 제한을 함께 정의한 뒤 등록한다. 애니메이션, 빠른 카메라 이동, 단순 시간 경과는 자체적으로 조언 사유가 아니다.

## 5. 먼저 말하기의 판단과 방해 억제

### 필수 판단 순서

1. 관찰·분석 동의, 현재 월드, 발언 모드, 비용·요청 한도를 확인한다.
2. 사건이 허용한 감시·목표·상황인지 확인한다.
3. 근거의 시점·식별 정확도·관찰 공백·단위 일치를 확인한다.
4. 같은 문제의 기존 조사·알림·거절 여부를 확인한다.
5. 발언이 사용자에게 지금 실행 가능한 확인·행동을 주는지 판단한다.
6. 화면 집중 상황, 사용자의 대화 입력·이전 답변 확인, 알림 빈도 한도를 확인한다.
7. 후보의 유효성을 다시 확인한 뒤 짧은 반응 또는 조용한 카드로 전달한다.

모델의 자신감 숫자만으로 근거 신뢰도를 결정하지 않는다. 화면에서 실제로 읽힌 정보, 사용자 확인, 비교 가능성으로 판단한다. 원인을 확정할 수 없으면 확인 요청으로 제한한다.

### 전달 우선순위

| 우선순위 | 상황 | 전달 원칙 |
| --- | --- | --- |
| 요청 응답 | 사용자가 질문·기억 수정·계획 변경 요청 | 가장 먼저 처리, 불필요한 선제 대화 중단 |
| 감시 문제 | 허용한 중요 문제의 새로운 변화 | 한 줄 알림 → 사용자가 열면 분석 카드 |
| 진행 확인 | 현재 조사·계획의 후속 결과 | 기존 스레드·카드 갱신 우선 |
| 비긴급 제안 | 배치 개선·다음 목표·성과 반응 | 기다렸다가 카드로 모음, 빈도 제한 |

### 시작값 후보 — 실제 플레이에서 조정

- 선제 팝업 전체: 최소 60초 간격, 10분 동안 최대 3회.
- 같은 월드·대상·증상: 최소 5분 중복 억제. 지속 관찰만으로 다시 알리지 않는다.
- 거절·닫기: 같은 제안은 해당 세션에서 억제한다. 사용자가 다시 요청하면 해제할 수 있다.
- 문제 악화·새 증거: 기존 카드 갱신이 우선이다. 새 팝업은 사용자가 허용한 악화 조건과 전체 제한을 통과해야 한다.
- 대기한 알림은 전달 직전 재평가한다. 이미 해결·목표 변경·월드 전환된 후보는 폐기한다.
- 알림 소리는 기본 OFF다. 음성은 후속 기능이며 발언 빈도·취소 정책을 그대로 적용한다.

숫자는 성능·서비스 약속이 아니다. 사용자가 빈도를 낮추거나 해당 상황을 끌 수 있어야 한다. 중복 판단은 월드·대상·증상과 문제 리비전을 기준으로 하고 모델 표현이 바뀌었다고 새 사건으로 취급하지 않는다.

### 침묵해야 하는 경우

- 사용자가 조용한 모드, 해당 감시 OFF, 관찰 중지 또는 API 분석 한도 도달 상태다.
- 원인·대상·월드가 불분명하고 가치 있는 확인 행동도 없다.
- 사용자가 해당 계획을 취소·보류하거나 같은 제안을 거절했다.
- 새 정보가 없는 동일한 경고·시설을 반복해서 보고 있다.
- 빠른 화면 전환·전투·메뉴 조작 등으로 방해가 예상된다. 확실히 구분하지 못하면 비긴급 알림은 보류한다.
- 관찰 공백 뒤 최신 상태를 아직 확인하지 못했다.

비용·캡처·인증 오류는 게임 조언과 구분해 상태 영역에서 안내한다. “모든 알림 OFF”는 앱의 실패 상태를 성공처럼 숨기는 설정이 아니다.

## 6. 화면 안에서 어떻게 보여주는가

- 게임 위에서는 작은 동료 아이콘+말풍선이 기본이다. 이름을 끌어 위치를 옮기고 아이콘·질문 단축키로 대화창을 펼친다. 대기·관찰·생각 중 표시와 움직임 줄이기를 제공한다. 큰 창에서는 기존 대화·기억·경험을 이어간다.
- 새 답변의 말풍선은 20초 뒤 접히며 기록은 대화창에 남는다. 오래된 기록은 새 발언으로 다시 띄우지 않는다. 답변에 실제 근거 이미지가 있으면 미리보기로 연결하고, 클릭 후 대화창에서 확대·원본 비교·정정을 한다. 미리보기는 기록 화면이며 현재 게임 위치 표시가 아니다.
- 선제 알림은 한 줄과 `자세히`, `나중에`, `이 문제 알림 끄기` 액션을 제공한다. 게임 입력을 강제로 빼앗지 않는다.
- 시각적 설명은 캡처 위에 표시한다. 번호를 누르면 해당 설명과 확대 이미지로 이동한다.
- 도움 답변에는 같은 근거의 이미지 카드를 바로 표시한다. 확대창에서 표시 없는 원본과 비교하고, 잘못 짚은 위치는 그 이미지가 연결된 정정 질문으로 이어간다. 기본 질문의 최근 두 이미지 비교와 명시적으로 선택한 한 이미지 질문을 구분한다.
- 캡처가 과거 시점이면 시각과 `기록 화면` 표시를 유지한다. 현재 게임 화면 위의 실시간 위치 표시로 오해하게 하지 않는다.
- 동료의 투명한 빈 영역은 클릭을 게임으로 통과시키며, 아이콘·말풍선·버튼만 마우스 입력을 받는다. 호버·말풍선 도착은 키보드 포커스를 가져오지 않는다. 아이콘 클릭 또는 질문 단축키로 입력 모드를 열며, 보내기·Esc·같은 키로 질문 직전의 창에 복귀한다. 전송 후 분석과 화면 관찰은 계속되고 답변 도착은 포커스를 바꾸지 않는다. 숨기기 키와 큰 창 복귀도 제공한다.
- 질문 단축키 등록 충돌은 대체 키를 표시하고, 모두 실패하면 마우스 입력을 유지한다. 창 모드·테두리 없는 전체 화면을 지원 기준으로 두며, 독점 전체 화면·관리자 권한 차이는 실제 게임 호환성 검증을 남긴다. 대화창의 근거 이미지는 기록 시점 자료이며 게임의 현재 좌표 위에 정렬된 표시가 아니다.
- 중요한 영역 1–3개부터 표시한다. 색상에 번호·모양·텍스트를 함께 사용한다.
- 분석을 기다리는 동안 “최근 관찰과 지난 기록을 확인 중”과 같은 상태를 표시한다. 아직 확인하지 않은 원인을 먼저 단정하지 않는다.
- 새 화면이 도착하면 기존 결론에 영향을 주는지 평가한다. 결론 변경은 명시적으로 안내하고 표시 근거를 갱신한다.

### 현재 게임 화면을 짚는 설명 — 추가 구현 목표

기존 대화 오버레이는 대화창을 게임 위에 띄운다. 현재 위치 표시는 게임의 대상 바로 위에 원·화살표·번호를 정렬하는 별도 기능이다. 캡처 위 표시, 현재 위치 표시와 제공 상태를 구분한다.

- “이쪽부터 볼까?”라는 대사와 대상 표시를 연결하며 핵심 대상 1–3개만 강조한다. 생성 이미지는 실제 대상 표시의 필수 요소가 아니다.
- 현재 화면에 표시하기 직전 대상·장면·좌표·관련 상태를 다시 확인한다. 요청 지연만으로 유효성을 확정하거나 무효화하지 않는다.
- 카메라 이동·줌·메뉴·창·배율 변경·관찰 공백·월드 전환 후에는 옛 좌표 표시를 숨긴다. 대상의 재확인이 가능할 때만 갱신한다.
- 정확히 짚을 수 없으면 시각이 있는 근거 캡처로 설명하고 대상 선택을 요청한다. 과거 캡처를 현재 게임 위치에 붙이지 않는다.
- 표시가 게임 조작을 가로막지 않으며, 사용자는 현재 설명을 닫거나 현재 위치 표시를 끌 수 있다. 함께 플레이의 선제 제안에는 기존 발언 정책을 그대로 적용한다.

## 7. 질문 의도별 응답 템플릿

| 질문 의도 | 먼저 말할 내용 | 시각 자료 | 후속 액션 |
| --- | --- | --- | --- |
| “왜 이렇게 됐어?” | 확인된 변화와 가능성이 높은 설명, 남은 불확실성 | 과거·현재 비교 또는 관련 화면 묶음 | 확인 화면 보기, 원인 조사 계속 |
| “어디가 문제야?” | 확인 가능한 대상 또는 문제 후보 | 번호·원·영역 표시 | 대상 확대, 관련 통계 확인 |
| “지금 뭐부터 해?” | 현재 목표에 맞는 첫 행동과 이유 | 필요한 경우 관련 대상 표시 | 계획에 추가, 다른 목표 선택 |
| “A와 B 중 뭐가 좋아?” | 사용자 조건에 따른 추천 또는 조건부 비교 | 두 후보의 도면·관련 캡처 비교 | 최소 변경/확장성 등 기준 변경 |
| “여기 배치 좀 개선해줘” | 유지 조건·공간 정보 확인, 개선 방향 | 현재 표시 + 제안 도면 | 기존 시설 유지, 더 간단한 안, 상세 설계 |
| “지난번에 뭐 하려 했지?” | 기록된 목표·마지막 결정·첫 행동 | 당시 근거 화면, 현재 관찰과 구분 | 계속하기, 계획 변경 |
| “효과 있었어?” | 관찰한 전후 변화와 아직 확인 못한 결과 | 실제 전후 화면·수치 비교 | 더 관찰하기, 해결 확인, 원안 재검토 |
| “이게 뭐야?” | 대상 식별·기능 설명, 불명확하면 대상 확인 | 선택 위치 확대 | 게임 규칙 보기, 관련 계획 연결 |
| “이걸 어떻게 설정해?” | 개념·준비물·설정 순서를 구분해 안내 | 실제 UI 확보 시 단계별 번호 표시, 미확보 시 개념도 | 한 단계씩 따라하기, 설정 확인, 실제 동작 검증 |

도움 요청의 기본 카드 순서는 **짧은 결론 → 근거 이미지 → 지금 할 행동 하나**다. 이유와 나머지 단계·조건은 펼쳐본다. 잡담에는 행동을 억지로 붙이지 않는다. 상세 분석에는 후보 비교·버전·시점·추정·검증 방법을 포함한다. 정보가 부족하면 현재 말할 수 있는 부분부터 설명하고, 답을 바꿀 핵심 정보 하나부터 요청한다.

사용자가 “이거”, “여기”라고 말하면 선택 영역·현재 화면·최근 대화로 대상을 찾는다. 후보가 여러 개이면 표시된 후보 중 선택하게 한다. 그럴듯한 시설 하나를 임의로 확정하지 않는다.

## 8. 다중 턴 조사와 계획의 생애주기

```text
변화 감지 → 조사 후보
  → 사용자 질문 또는 허용된 감시 알림
  → 확인된 사실·가설·추가 정보
  → 개선안 제시
  → 사용자 수락/보류/거절
  → 실제 적용 여부 확인
  → 결과 관찰
  → 해결 확인 / 일부 개선 / 재조사
```

- 사용자 수락은 실행 완료가 아니다. 사용자가 적용했다고 말하거나 실제 변경을 관찰하기 전에는 `제안 수락` 상태로 둔다.
- 적용 확인과 효과 확인도 별개다. 생산시설을 옮겼다고 문제 해결을 자동 선언하지 않는다.
- 사용자가 “적용했어”라고 말하면 사용자 진술로 기록하고 결과를 관찰한다.
- 결과가 잠깐 좋아진 것만으로 지속 해결을 확정하지 않는다. 게임 상황에 맞는 관찰 기간·통계를 확인한다.
- 보류는 이유·재검토 조건과 함께 기록할 수 있다. 거절은 같은 권유의 반복을 억제한다.
- “아니, 원래 이쪽이 문제야”는 사용자 정정으로 처리해 조사 대상을 바꾼다.
- 문제가 재발하면 이전 조치와 이번 차이를 비교한다. 지난 해결을 삭제하거나 실패라고 임의로 바꾸지 않는다.
- 조사 스레드에는 관련 월드·목표·대상·근거·가설·계획 상태를 유지한다.
- 조사에서 얻은 경험은 제안·사용자 선택·실제 적용·비교 조건·결과·반례를 연결해 저장한다. 다른 요소도 바뀌었거나 결과를 볼 수 없으면 효과 미확인으로 남긴다.
- 원본 이미지의 자동 만료로 대화·후속 경험을 연쇄 삭제하지 않는다. 근거 만료와 재검토 상태를 표시한다. 사용자 명시적 삭제·정정은 파생 내용에도 반영한다.

## 9. 실제 대화 형태 예시

아래 게임 예시는 서비스 동작 설명이다. 해당 게임의 모든 버전·모드에 대한 규칙 지원이나 정확한 설계 완료를 뜻하지 않는다.

### 예시 A — Anno: 커피 부족의 원인 조사 / SC-02

**가정:** 주거 지역 확장과 이후 재고 감소를 관찰했다. 생산·소비 통계와 항로 화면은 아직 보지 못했다. 커피 문제 감시는 사용자가 허용했다.

선제 알림:

> “주거 지역을 확장한 뒤 커피 재고가 줄고 있어요. 공급 쪽을 함께 확인할까요?”

액션: `조사하기` / `나중에` / `이 문제 알림 끄기`

사용자: “응, 왜 이러지?”

기본 답변:

> “현재 확인한 건 주거 확장 뒤 재고가 감소했다는 점이에요. 소비 증가 가능성은 있지만, 생산 부족인지 운송 문제인지는 아직 구분되지 않아요. 생산·소비 통계를 보여주면 먼저 공급량부터 확인할게요.”

시각 자료: 이전 주거 지역과 이후 재고 표시를 나란히 배치. 각 시점을 표시하며 원인 확정 표시는 하지 않는다.

다음 턴에서 통계·항로 화면을 받으면 확인된 수치와 실제 운송 상태에 따라 가설을 갱신한다. 예시를 위해 “증설하면 해결” 같은 결론을 미리 고정하지 않는다.

### 예시 B — Factorio: 이 벨트가 병목인가? / SC-03

사용자: “이 벨트 늘리면 해결될까?”

**가정:** 현재 캡처에서 일부 설비의 입력 부족은 확인된다. 벨트 처리량과 상류 공급량은 확인하지 못했다.

> “① 구역의 입력 부족은 보여요. 다만 벨트 용량이 부족한지, 앞쪽 생산이 부족한지는 이 화면만으로 구분하기 어려워요. ② 상류 구역까지 보면 벨트 확장과 공급 증설 중 무엇을 먼저 할지 좁힐 수 있어요.”

시각 자료: ① 입력 부족이 확인된 구역, ② 추가 관찰이 필요한 화면 방향을 표시. 화면 밖 설비를 실제 존재하는 것처럼 그리지 않는다.

액션: `상류 화면으로 계속 조사` / `관련 생산 계획 보기`

### 예시 C — 배치 설계: 최소 변경과 확장성 비교 / SC-08

사용자: “여기 좀 더 깔끔하게 배치해줘. 기존 공장은 최대한 유지하고.”

> “기존 시설 유지가 우선이면 A안부터 추천해요. 현재 확인한 공간에서 연결 동선을 정리하는 방향이에요. B안은 확장 여유를 더 두지만 시설 이동이 늘어요. 정확한 배치는 건물 규격과 사용 가능한 공간을 확인한 뒤 검증할 수 있어요.”

시각 자료:

- 현재 캡처: 유지할 시설·변경 후보·확인할 공간 표시.
- A안: 최소 변경 개념 도면.
- B안: 확장 우선 개념 도면.
- 각 도면에 `제안 — 미적용`, 규격 검증 여부, 추가로 필요한 정보를 표시.

액션: `A안으로 구체화` / `확장성 우선` / `유지할 시설 선택`

생산량 증가율·정확한 건설 비용은 계산 근거가 있을 때만 제시한다.

### 예시 D — Satisfactory: 3D 공간 정보가 부족할 때 / SC-08

사용자: “위층으로 올리는 게 좋을까?”

> “현재 화면에서는 기존 연결과 위층 공간을 함께 확인하기 어려워요. 확장 방향을 비교하려면 옆면이나 위쪽에서 본 화면이 하나 더 필요해요. 우선 평면 확장과 수직 확장의 장단점은 비교해드릴게요.”

시각 자료: 현재 보이는 영역만 표시하고 확인이 필요한 시점을 안내한다. 임의의 층 높이·연결 경로를 검증된 도면처럼 만들지 않는다.

### 예시 E — 복귀 브리핑과 목표 변경 / SC-01

> “지난번에는 공급을 안정화한 뒤 주거 지역을 확장하려고 했어요. 마지막으로 보류한 건 생산시설 증설이었고요. 오늘은 현재 재고와 공급 상태부터 다시 확인하면 좋겠어요.”

액션: `이 계획 계속` / `오늘 목표 바꾸기` / `지난 기록 보기`

사용자: “오늘은 효율보다 도시 미관부터 정리할래.”

> “오늘 목표를 미관 정리로 바꿀게요. 이전 공급 안정화 계획은 보류로 남겨두고, 유지하고 싶은 구역부터 확인해볼게요.”

기억 갱신: 오늘 목표 변경, 기존 계획 보류. 모든 향후 추천이 영구적으로 미관 우선이라고 일반화하지 않는다.

### 예시 F — 조치 후 검증과 오류 수정 / SC-09

사용자: “항로 조정했어. 이제 괜찮지?”

> “적용했다고 기록했어요. 효과는 새 재고·운송 상태를 조금 더 확인해야 해요. 조정 전 화면과 지금 화면을 비교해서 부족이 계속되는지 보겠습니다.”

결과가 확인되면:

> “비교한 구간에서는 재고 감소가 멈췄어요. 이번 조치가 도움이 된 것으로 보이지만, 장기 공급 안정 여부는 아직 더 확인해야 해요.”

오류가 드러나면:

> “앞서 ①을 문제 대상으로 짚은 건 잘못됐어요. 새 화면에서는 ②가 관련 구역으로 확인됩니다. 표시와 조사 기록을 수정하고 여기서 이어갈게요.”

틀린 추정을 조용히 사실로 덮어쓰지 않는다. 수정한 이유·근거와 사용자의 정정을 기록한다.

### 사용자 제공 사례 — 낯선 기능의 학습 / SC-11

[홉 섬과 메인섬의 무역로 배우기](cases/ANNO_HOPS_TRADE_ROUTE.md)는 사용자가 실제로 설명한 첫 사례다. 이번 로컬 구현에서 대표 영상 프레임은 확인했으나 무역로·생산 통계·왕복 시간은 미확인이다. 사용자 진술, 영상에서 읽은 내용과 일반 규칙 기반 제안을 구분한다.

이 경우 동료는 문제 원인 조사뿐 아니라 **개념 설명 → 준비 확인 → 단계별 설정 → 적정 운송량 판단 → 실제 동작 확인**의 학습 흐름을 제공한다. 사용자가 기능을 모른다는 이유로 모든 상태 정보를 먼저 요구하지 않는다.

## 10. 사용자 제어와 피드백

답변·알림에서 다음 조작을 제공한다. 모든 조작을 한 카드에 동시에 펼치지 않고 상황에 맞는 것부터 노출한다.

- 도움 강도: `힌트만`, `비교해줘`, `추천해줘`.
- 길이: `짧게`, `자세히`.
- 근거: `어떤 화면을 봤어?`, `지난 기록 보기`, `대상 확대`.
- 계획: `계획에 추가`, `보류`, `취소`, `목표 변경`.
- 결과: `적용했어`, `해결됐어`, `아직 문제야`.
- 정정: `잘못 봤어`, `기억 수정`, `다른 대상이야`.
- 알림: `나중에`, `이 문제 알림 끄기`, `이번 세션은 조용히`.

“좋아요” 피드백을 해결 확인으로 바꾸지 않는다. 사용자 피드백은 제품 품질 신호와 월드 상태 변경을 구분해서 처리한다. 반복 거절은 발언을 줄이는 데 쓰되 취향을 영구 변경하려면 사용자가 확인할 수 있어야 한다.

## 11. 스포일러·지식 수준·취향

- 스포일러 설정은 게임·월드별로 유지한다: 힌트, 현재 진행 범위, 전체 공략 허용.
- 미래 해금·연구·스토리·이벤트가 포함된 설명은 설정과 현재 진행을 확인한다. 확실하지 않으면 최소 범위로 답한다.
- 초보자 설명은 용어·확인 경로를 포함한다. 숙련자 설명은 이미 확인한 내용과 기초 설명을 줄인다.
- 숙련도는 사용자 설정과 명시적인 피드백을 우선한다. 오래 플레이했다고 자동으로 전문가로 분류하지 않는다.
- 미관·효율·최소 변경·확장성 선호는 전역 기본값과 현재 월드·현재 요청을 구분한다.

## 12. AI 출력과 전달 정책의 책임 분리

모델은 사건 해석·응답 후보·근거 연결·표시 후보를 만든다. 앱은 발언 권한, 한도, 중복, 최신성, 실제 렌더링, 기억 저장을 검증한다. 모델이 사용자 설정을 무시하고 직접 팝업·기억 확정·게임 행동을 실행할 수 없다.

### 응답 계약의 필수 필드

| 필드 | 의미·검증 |
| --- | --- |
| `world_id`, `thread_id`, `context_revision` | 원래 월드·조사·맥락 버전에 연결, 늦은 응답 귀속 검사 |
| `intent`, `trigger_id` | 요청 의도와 SC 상황 ID. 사용자 요청과 선제 후보 구분 |
| `summary` | 짧은 첫 답변, 원인 확정 여부 검토 |
| `facts`, `hypotheses`, `missing_information` | 사실·가설·부족한 정보를 분리 |
| `evidence_refs` | 실제 접근 가능한 같은 월드의 근거 ID·시점 |
| `visuals` | 허용 도형·원본 이미지 ID·좌표·설명, 범위 검사 |
| `suggestions`, `next_actions` | 제안·선택지·확인 행동, 계산 근거·적용 조건 |
| `memory_proposals` | 사건·목표·결정 기록 후보. 확정은 앱의 기억 규칙을 따름 |
| `validity_conditions` | 답변이 유효한 상태·새 관찰로 재검토할 조건 |
| `learning_episode_refs`, `learning_proposals` | 관련 과거 경험과 새 경험 후보, 적용 범위·미확인·반례. 앱이 출처·상태·연결을 검증 |
| `live_anchor` — 현재 위치 표시 사용 시 | 원본 프레임·대상·세션·창 영역·좌표계·재확인 조건. 앱이 최신 관찰과 좌표 변환을 검증하며 불확실하면 숨김 |

존재하지 않는 근거, 다른 월드 ID, 잘못된 좌표, 실행 가능한 임의 콘텐츠는 차단한다. 일부 시각 자료가 실패하면 설명과 오류 상태를 제공하고 잘못된 이미지를 정상 답변처럼 보여주지 않는다.

## 13. 행동 명세의 검증

PLAN의 AT-29–42와 연결한다. 순수 전달 정책은 고정된 시계·사건을 사용하는 자동 시험으로, 실제 이해·표시·유용성은 화면 리플레이와 플레이 검토로 검증한다. 현재 위치 정렬은 활성화하려는 OS·게임 창 모드에서 별도로 검증한다.

- 같은 관찰을 반복해도 같은 팝업이 계속 뜨지 않는다.
- 조용한 모드에서는 선제 게임 발언이 없고 사용자 질문은 답한다.
- 목표·모드·월드 변경 뒤 대기한 알림이 잘못 전달되지 않는다.
- 같은 질문을 여러 게임에 적용해도 게임 규칙과 기억이 섞이지 않는다.
- 제안 수락, 적용, 효과 확인, 해결 상태가 구분된다.
- 예시 A–F의 정보 부족·정정·계획 변경이 실제 출력에 반영된다.
- 이미지 답변의 대상·시점·제안 여부를 사용자가 구분할 수 있다.
- 사용자 알림 거절·정정이 다음 반응에 반영된다.
- 사전 지식 부족·실패·반례를 포함한 공동 학습 경험이 저장되고 최근 대화 밖에서도 관련 경험을 회수한다.
- 느린 모델 응답과 화면 이동을 함께 재현해 현재 위치 표시의 재검증·해제와 근거 캡처 전환을 확인한다.

행동 개선 지표는 선제 알림의 유용성·닫기·차단 비율, 중복 발언, 사용자 정정, 질문 후 실행 가능한 다음 행동, 시각 자료 이해도를 포함한다. 원문을 기본 텔레메트리로 수집하지 않고 동의 범위의 최소 이벤트를 사용한다. 반응 수가 늘었다는 사실을 성공으로 간주하지 않는다.
