# 함께 배우는 동료와 현재 화면 설명

> 상태: 제품·행동 명세 v0.1 / 2026-10-07 — 구현 목표, 완료 기록이 아님
> 상위 문서: [PLAN](../PLAN.md), [컴패니언 행동 명세](COMPANION_BEHAVIOR.md)
> 연결: FR-05–10·22–26, AT-37–42
> 예시는 가상의 플레이 흐름이며 실제 첨부 영상이나 현재 게임을 관찰한 결과가 아니다.

## 1. 원하는 경험

사용자가 게임을 시작하면 동료도 같은 장면과 대화에서 배운다. 새로운 시스템을 만나면 같이 알아보고, 작은 제안을 시험하고, 결과를 다음 선택에 활용한다. 사용자는 플레이하며 판단하고, 동료는 관찰·설명·경험 기억을 맡는다.

> “여기에 재료가 쌓이는 건 봤는데, 왜 다음 공장이 멈추는지는 아직 모르겠어. 이 연결부터 같이 확인해볼까?”
>
> “이번 변경 뒤에는 공급이 이어졌네. 이 조건에선 도움이 됐던 경험으로 기억해둘게.”

대사는 짧게 유지한다. 모든 대화를 실험으로 만들거나 학습 상태를 매번 설명하지 않는다. 잡담·꾸미기·탐험·실패를 즐기는 플레이도 이어갈 수 있다.

## 2. 무엇을 배운다고 하는가

학습의 첫 구현은 모델에 보낼 경험을 앱이 저장·검색·갱신하는 방식이다. 모델이나 API 제공자를 바꿔도 경험을 유지한다. 모델 가중치 재학습·전체 영상 상시 전송은 선행 조건이 아니다.

| 지식 | 예시 | 취급 |
| --- | --- | --- |
| 사전 게임 지식 | 게임 설명, 검증한 공식 규칙 | 출처·버전·모드 적용 범위를 확인. 모델의 기억만 있으면 미검증 정보 |
| 현재 관찰 | 재고 수치, 경고, 보이는 연결 | 프레임·대상·시점과 연결. 화면 밖 상태는 미확인 |
| 사용자 설명·선택 | “이 섬은 관광용으로 남겨둘게” | 사용자 출처로 저장. AI 제안과 구분 |
| 가설 | 운송 지연 때문에 공급이 끊겼을 가능성 | 근거·확인 방법·반증 조건과 연결 |
| 함께 얻은 경험 | 특정 변경 후 이번 월드에서 재고가 회복됨 | 비교 조건·결과·미확인·반례를 유지. 보편 규칙으로 승격하지 않음 |
| 취향 | 기존 건물 유지, 보기 좋은 배치 선호 | 명시적 선호와 해당 세션 요청을 구분. 다른 월드로 공유하는 범위는 기존 기억 정책 적용 |

게임의 내부 수치나 모든 규칙을 화면만으로 알아낼 수는 없다. 필요한 정보가 없으면 관련 통계·설정 화면을 함께 보거나 사용자가 알려준 내용을 활용한다. 사전 지식과 관찰이 충돌하면 현재 버전·모드·대상을 확인하고 충돌을 기록한다.

## 3. 공동 학습 흐름

```text
현재 목표·화면·관련 경험 확인
  → 새 관찰 또는 사용자 질문
  → 확인된 사실과 가설 분리
  → 확인 대상 표시 + 작은 제안
  → 사용자 선택 / 보류 / 거절
  → 실제 적용 확인
  → 비교 가능한 결과 관찰
  → 경험 저장·수정
  → 다음 유사 상황에서 검색·조건 재확인
```

### 관찰에서 제안으로

- 최근 버퍼에서 변경 전·중요 변화·결과 프레임을 골라 하나의 경험에 연결한다. 매 프레임 원격 호출은 기본 동작으로 사용하지 않는다.
- 질문·활성 목표·허용된 감시와 관련된 대상을 우선한다. 화면 변화만으로 사용자 의도나 병목을 확정하지 않는다.
- 아직 모르는 이유는 짧게 말하고, 답을 바꿀 핵심 확인 행동 하나부터 제안한다.
- 가능한 한 작은 변경 하나를 권한다. 자원·위험·기존 배치 유지·되돌리기 가능성을 고려한다. 자동 조작은 하지 않는다.
- 함께 플레이 모드의 선제 제안은 새로운 근거와 실행 가능한 가치가 있을 때만 기존 빈도·집중·거절 정책을 통과한다. 조용한 모드에서는 요청에 답한다.

### 결과에서 경험으로

- 제안·수락·실제 적용·효과 확인은 별개로 기록한다.
- 생산 주기·운송 왕복 등 결과가 나타날 조건을 정한다. 실제 게임 일시정지·속도와 관찰 공백을 고려하고, 임의의 벽시계 대기만으로 효과를 확정하지 않는다.
- 가능하면 같은 대상·단위·화면 기준의 전후 상태를 비교한다. 여러 변경이 동시에 있었다면 원인을 분리하지 못했다고 남긴다.
- 실패도 원래 가설과 함께 기록하고 다음 시도를 조정한다. 조건이 바뀌지 않았는데 같은 실패·거절안을 계속 권하지 않는다.
- 기억 저장은 중요한 선택·시도에 집중한다. 사용자 선택과 결과를 연결하는 경험 기록을 위해 매번 수동 메모를 요구하지 않는다.

### 경험의 상태

`가설 후보 → 시도 대기 → 적용 확인 → 결과 관찰 → 이번 조건의 경험`

결과에는 `개선 관찰`, `효과 미확인`, `악화 관찰`을 구분한다. 반복된 비교 가능한 관찰은 해당 조건의 신뢰를 높일 수 있다. 반례·정정·버전 변경·관련 근거 만료가 있으면 `충돌 / 재검토 필요`로 갱신한다. 모델의 자신감 숫자나 반복 발화는 검증 근거가 아니다.

## 4. 무엇을 기억하고 다시 찾는가

경험 하나에는 다음 정보를 연결한다. 별도 거대 지식 그래프 없이 기존 월드 기록과 ID 연결로 시작해도 된다.

| 정보 | 목적 |
| --- | --- |
| 게임·버전·모드·월드·관련 대상 | 다른 상황에 무조건 적용하지 않기 |
| 질문·당시 목표·사용자 결정 | 무엇을 왜 함께 시도했는지 복원 |
| 전후 관찰·근거 ID·시점 | 어떤 변화가 실제로 보였는지 설명 |
| 가설·제안·적용 여부·확인 조건 | 제안과 실제 행동, 추정을 구분 |
| 결과·동시 변경·미확인·반례 | 효과를 과장하지 않고 재검토 |
| 기록 리비전·출처·삭제·근거 만료 상태 | 정정·보관 정책·검색을 일관되게 적용 |

- 최근 대화와 관련 장기 경험을 함께 검색한다. 대화에만 남긴 결정도 최근 12턴 밖에서 회수할 수 있어야 한다.
- 관련 경험을 추천에 사용할 때 당시 조건과 현재 차이를 확인한다. 다른 월드의 교훈은 출처를 유지해 참고하고, 그 월드의 상태를 현재 사실로 옮기지 않는다.
- “이건 아니야”, “다른 이유였어”, “이 시도는 취소해”를 경험과 관련 검색에 반영한다.
- 이미지 자동 만료 시 텍스트 대화·결정·경험을 연쇄 삭제하지 않는다. 원본을 열 수 없다는 상태와 재검토 필요성을 남긴다. 명시적 사용자 삭제·정정은 관련 파생 내용에 반영해 삭제된 정보를 다시 활용하지 않는다.
- 답변에서 사용한 근거는 최근 프레임 목록의 개수 제한과 별개로 불러온다. 파일이 남아 있으면 해당 답변에서 열 수 있어야 한다.

## 5. 화면을 함께 보며 설명하는 방식

이미지는 같은 대상에 시선을 맞추는 수단이다. 위치·배치·원인 설명은 실제 게임 화면 위의 원·화살표·번호와 짧은 대사를 연결한다. 확인한 대상만 표시하며, 개념도는 실제 배치와 구분한다.

| 표시 방식 | 사용자 경험 | 지원 조건 |
| --- | --- | --- |
| 대화 오버레이 | 게임 위 작은 대화창에서 대화를 이어감 | 기존 구현. 현재 게임 대상과 좌표가 정렬된 표시는 아님 |
| 근거 캡처 설명 | 같은 장면의 캡처에 표시하고 확대·원본·전후 비교 | 캡처 시각과 과거 여부를 유지. 현재 답변의 참조 이미지 조회 |
| 현재 위치 표시 | 실제 게임의 대상 위에 번호·원·화살표와 짧은 설명 | 추가 구현. 최신 대상 확인·좌표 변환·표시 중 재검증이 가능한 지원 범위 |

사용자가 “여기 어떻게 해?”라고 물으면 현재 화면과 선택 영역으로 대상을 확인한다. 다른 메뉴나 구역이 필요하면 해당 화면을 요청한다. 원본을 갖고 있지 않은 버튼이나 건물에 그럴듯한 표시를 만들어 붙이지 않는다.

### 현재 위치 표시의 전달 계약

1. 모델이 원본 프레임·대상·표시 후보·설명을 반환한다.
2. 앱이 동일 월드·캡처 세션·창과 최신 화면에서 대상과 관련 상태가 여전히 유효한지 확인한다.
3. 캡처 영역·자르기·축소·클라이언트 영역·DPI·레터박스 변환을 검증하고 게임의 표시 위치에 매핑한다.
4. 확인된 대상 1–3개를 입력 통과 방식으로 표시한다. 현재 설명 종료·표시 OFF를 제공한다.
5. 표시 중 로컬 프레임으로 유효성을 확인한다. 화면 이동·줌·UI·창·배율 변경 시 우선 숨기고, 대상과 새 좌표를 다시 확인할 수 있을 때 갱신한다.
6. 관찰 중지·공백·검은 화면·창 종료·월드 변경·사용자 닫기 후 표시를 제거한다. 재확인 불가 시 시각이 있는 근거 캡처로 설명을 이어간다.

화면 표시 좌표가 같아도 재고·선택 상태·추천 조건이 바뀔 수 있다. 위치와 설명 내용의 유효성을 함께 확인한다. 전체 화면 밝기 차이만으로 대상을 계속 추적할 수 있다고 판단하지 않는다. 사라진 대상을 다른 비슷한 건물에 임의로 재연결하지 않는다.

모델 응답이 24–45초 걸려도 최신 화면에서 재검증 가능한 후보는 평가할 수 있다. 단순히 지난 초 수만으로 실시간 후보를 계속 버리거나 과거 결과를 그대로 붙이지 않는다. 재검증된 현재 근거를 연결할 수 없으면 현재 위치 표시와 선제 전달을 보류하고 근거 캡처로 안내한다. 재검증에 추가 API 호출이 필요하면 기존 동의·예산 안에서만 수행한다.

창 모드·테두리 없는 전체 화면부터 실험한다. 독점 전체 화면·관리자 권한·3D 카메라 추적은 해당 환경 검증 후 지원 범위를 안내한다. 자동 카메라 이동·게임 조작·상시 이미지 생성은 이 경험의 선행 조건이 아니다.

## 6. Anno에서의 가상 대화

**가정:** 같은 월드에서 방금 두 섬의 재고와 항로 설정을 확인했다. 홉 섬에는 재고가 쌓이고 메인섬 재고는 줄었다. 항로 화면에서 낮은 홉 하역량을 확인했고, 사용자는 공급 문제를 함께 조사하도록 허용했다. 실제 첨부 영상에는 이 근거가 모두 확보되지 않았다.

동료:

> “방금 본 두 섬 재고를 보면 운송 쪽을 먼저 확인하면 좋겠어. 여기 홉 하역량부터 늘려볼까? 다음 왕복에 메인섬 재고가 회복되는지 보자.”

현재 항로 설정의 하역량을 표시한다. 현재 위치를 재확인할 수 없으면 그 설정을 관찰한 캡처 위에 표시한다. 다른 화면의 재고는 시각이 있는 전후 캡처로 함께 제공한다.

사용자: “늘렸어.”

동료:

> “좋아. 적용했다고 기록할게. 다음 도착 뒤 재고를 같이 보자.”

실제 도착 후 비교 가능한 재고가 늘었고 다른 변경을 확인하지 못한 상황:

> “다음 도착 뒤 재고가 회복됐네. 이번 조건에서는 도움이 된 경험으로 남겨둘게. 생산이나 소비가 바뀌면 다시 확인하자.”

다음 유사 상황에서는 당시 조건과 현재 차이를 확인하며 경험을 꺼낸다. 생산량·소비량·적재량·왕복 시간 없이 배 수나 영구 해결을 확정하지 않는다. 바뀐 요소를 충분히 관찰하지 못했다면 결과 원인은 미확정으로 남긴다.

## 7. 구현 순서와 확인할 증거

1. **기억·근거 보존:** 최근 12턴 밖의 결정 회수, 이미지 만료와 사용자 삭제 분리, 답변의 참조 이미지 조회를 먼저 안정화한다.
2. **공동 학습 한 사이클:** 실제 한 사례에서 가설·작은 변경·선택·적용·전후 결과를 저장하고, 재시작 후 유사 질문에서 다시 활용한다.
3. **캡처로 함께 설명:** 같은 근거의 번호·대사·확대·전후 비교를 연결하고 사용자 정정으로 대상을 갱신한다.
4. **현재 위치 표시 실험:** 지원 창 모드에서 실제 대상 정렬, 느린 모델 응답, 카메라·메뉴·DPI 변경과 표시 해제를 검증한다. 미검증 범위에서는 근거 캡처 설명을 유지한다.
5. **다른 게임에서 재사용:** 공장형 게임에서도 같은 경험 기록과 설명 흐름을 실행한다. 게임별 규칙은 출처·지원 수준을 유지한다.

검증은 PLAN의 AT-37–42와 연결한다. 기억·상태·변환·정책은 재현 가능한 자동 시험으로, 실제 장면 이해·같이 배운다는 느낌·표시 정확도·게임 입력 방해는 실제 PC 플레이로 검토한다. 모의 프레임·모의 모델 통과를 실제 게임 지원 완료로 표시하지 않는다.
